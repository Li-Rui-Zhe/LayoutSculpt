# 生成体验与断点恢复优化（2026-10-26）

## 用户实际看到的变化

- 主界面保留上传、风格、设计要求与选材；模型、强度、家具模式、AI 复核和人工核对偏好统一在高级设置中。默认精细家具、AI 复核、先看三维初稿。
- 新生成任务先用正式 GLB 建模器制作墙体、地板和门窗初稿，然后继续家具规划。初稿标注“尚未人工核对”，可旋转和缩放。
- 生成中的初稿只供查看，完整生成后才进入人工设计；初稿文件独立存放，不开放正式成果下载，避免混淆交付状态和覆盖人工修改。
- 仍可选择“先人工核对”。复核超时、无效复核结果等情况保留人工核对流程；普通核对页只需明确点击“已核对，继续生成”，去掉重复勾选。
- 失败或取消后默认“继续生成”，沿用原模型和参数，在同一个任务内复用有效检查点。更换模型重新生成是次级操作，创建独立版本。
- 登录失效、额度不足显示接入入口；家具未完成可直接“继续布置家具”，基于已保存方案建立新版本，保留原版本和人工草稿。

## 恢复与质量约束

- SQLite 事务重开失败/取消任务；使用用户看到的更新时间比较，旧请求不能再次重开下一轮失败。仍执行队列容量限制，成功任务不能重开。
- 等待上一轮 runner 完全退出再启动，同任务继续会重新订阅进度，不会被历史失败事件提前关闭连接。
- LangGraph 恢复继续验证任务 ID、原图摘要、参数与人工确认。没有检查点则从原输入重跑，阶段缓存仍可复用；不承诺所有历史任务都能跳过全部已完成阶段。
- 初稿与最终建模都保留来源校验；无效多边形、门窗失效引用等校验未取消。初稿写入临时目录，构建完成才发布。
- 自动几何检查和 AI 复核不会写入 `user_review`；只有明确人工确认才能标记 `source_reviewed=true`。
- 旧任务及不指定 `review_mode` 的 API 请求保持 `manual`；新前端明确提交 `preview`。
- 初稿增加一次本地建筑构建，不增加一次 AI 识别。它改善等待体验，不保证完整方案更早完成。自定义风格会在家具规划后补齐最终搭配。

## 验证

- 后端生成/工作流/可靠性专项：49 项通过；新增的启动恢复、复核降级、原图变更校验后，渐进生成专项 7 项全部通过（总计覆盖 52 项不同测试）。
- 前端现有单元测试 137 项通过；生产构建通过。
- 隔离浏览器服务：原有人工核对、手动修改导出等 7 组、异常恢复 4 组通过；渐进初稿与同任务继续 2 组通过。页面异常为空。
- 使用确定性 AI 替身测试链路，实际 GLB 构建和浏览器渲染；未调用真实付费 AI。
- 截图与报告：`data/visual-review/progressive/`。单独复验：`node scripts/prelaunch.mjs --progressive`。
