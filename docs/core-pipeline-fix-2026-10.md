# 户型生成核心链路修复

日期：2026-10-15。

## 现象与实际定位

原任务在 12% 户型识别阶段失败，约 73 秒内创建了两次 AI 会话，没有返回结构数据。页面统一显示“生成未完成”，掩盖了实际错误。真实错误为上游 `incomplete empty response (0 tokens)`，不是本地几何校验失败。

使用原图、原模型 `gpt-6-astra`、原推理强度 `high` 进行了以下对照：

| 请求 | 实际结果 |
| --- | --- |
| 最小图片可读性识别 | 约 9 秒成功，能说明主要空间分布 |
| 原完整识别契约 | 返回空响应 |
| 仅请求建筑结构的识别契约 | 两次成功，约 217 秒；包含完整坐标、墙体及开口 |
| 原复核契约 | 重试后仍空响应 |
| 精简房间属性后的复核契约 | 约 46 秒成功，补丁通过完整几何校验 |
| 普通家具格式，仅要求几行测试数据 | 约 5 秒成功 |
| 自定义风格家具格式，同样仅几行测试数据 | 约 28 秒空响应 |
| 自定义风格格式，将材质联合类型改为当前可用编号枚举 | 约 6 秒成功，仍包含 DIY 材质编号 |
| 修复后的真实家具规划及建模 | 一次请求成功；27 件家具，约 13.6 MB GLB，总计约 201 秒 |

证据指向当前本地 AI 服务对部分结构化输出契约的兼容性问题：例如材质字段中同为字符串的枚举/正则联合分支。不能由此断言所有模型或服务都不支持这种 JSON Schema；本次没有更换模型、降低推理强度或隐藏失败后使用模拟结果。

## 实现

1. **按阶段定义 AI 输出。** 识别不再要求填写编辑锁定、铺砖参数和材质引用；仍保留净空多边形、墙厚、门窗/通道、门朝向及有图像依据的铺装。
2. **复核只修改结构。** 保留原版本哈希、逐项图像依据和原子几何校验；更新房间/墙体时保留用户装修、承重标记和编辑属性。
3. **家具只返回布置数据。** 素材库模式通过 `asset_id` 引用内置和 DIY 素材，不要求 AI 重新输出部件。输入目录保留全部可选素材、尺寸、类别及变体，移除管理信息。示例家具阶段输入由 46,343 字符减至 29,140 字符。
4. **材质用本次目录约束。** 自定义风格的墙地面字段直接枚举本次用途对应的所有可用编号，包括用户 DIY 贴图；运行时继续校验真实目录。不更改保存格式，不限制用户可创建的材质类型。
5. **错误保留结构化分类。** 处理上游 `error` 通知及 `willRetry`，等待正式终态，不把上游恢复中的通知提前判为失败。空响应、限流、额度、登录、模型、输出格式、连接和超时分别处理。任务指标只记录安全字段。
6. **重试有上限。** 可恢复的临时故障最多额外请求一次，限流退避 5 秒，其余退避 1 秒；总阶段超时预算不变。身份/模型/请求错误不盲目重试。
7. **阶段状态明确。** 请求已被接收、开始返回结果、自动恢复、校验/修正均有对应状态；同一会话重复的恢复通知合并显示。

## 验证与边界

- 后端全量回归 436 项通过；材质目录枚举等最后调整另外完成 45 项针对性回归。
- 新增回归覆盖：精简契约贯穿流程、无损坐标往返、装修属性保留、全部素材可用、DIY 材质枚举、空响应重试上限、协议错误分类、上游重试与旧 turn 通知隔离。
- 真实 GLB 的轮廓/几何截面一致性通过；27 件家具的布局检查没有报告问题。自动补充 5 盏可编辑灯具。
- 最后通过真实 `POST /api/jobs` 上传原图（隔离数据库、无缓存）：识别约 229 秒、复核约 47 秒，均一次请求通过；约 281 秒进入 `awaiting_review`，`ai_review.status=completed`。
- 尺寸仍来自无标注原图的估算，必须在人工核对环节确认；机器几何检查通过不等于施工准确性。
- 原失败任务保留。首次重试已进入人工核对；隔离目录中的建模测试使用 `diagnostic_validation`，没有代替用户确认真实任务，也没有把测试结果写成用户已审核。
- 真实测试文件、模型及任务数据库位于被 Git 忽略的 `data/review/`，不进入内置素材或代码提交。
- 本地前后端已重启加载修复，8000 健康检查及 5173 页面均返回正常。
