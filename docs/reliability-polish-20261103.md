# 生成验收、草稿恢复与编辑减负（2026-11-03）

## 用户能感受到的变化

- 后端暂时不可用时，有本地原始基线的设计可恢复编辑草稿。连接恢复后自动读取并合并独立修改；真正冲突仍保留双方版本供选择，不静默覆盖。不需要用户先刷新或重新读取。
- 重连读取使用当前最新草稿，不使用开始请求时的旧快照。离开项目会取消请求和重试，迟到响应不写入其他项目。
- 保存栏区分“草稿保存中”“草稿已保存到本机”“草稿保存需处理”，只有保存成功才显示对勾；同时单独说明三维版本是否需要更新。AI 建议预览不被标成已保存设计。
- 家具属性先显示更换、旋转、尺寸和位置；商品试摆、家具联动后置。联动列表展开后才挂载。独立抽出 `FurnitureExtras`，不扩大主编辑组件职责。
- 草稿差异和单件 AI 基线只随文档变化重新计算，选中对象、提示变化等不会反复序列化整屋草稿。没有降低模型几何或导出精度。
- 交互诊断补充长帧数量与最差帧间隔，超过 250 ms 的卡顿不再被排除；空闲时间仍不计入。只在本地开启诊断时记录，不上传。

## 边界

本地恢复需要此前在本版本中打开过设计并成功保存原始基线，且浏览器存储仍可用；不等于首次离线启动整个应用、离线 AI 生成或离线加载所有 GLB。服务恢复后，对已同步基线做三方合并；冲突不自动覆盖。浏览器存储不足仍明确提示，不能保证被浏览器主动清理的数据可恢复。

## 真实图纸质量验收入口

新增 `scripts/quality_cases.py` 和 `benchmark_quality.py --manifest`。测试图与标注应由维护者合法取得并独立核对，不能由待测 AI 自己生成答案后给自己评分。

目录示例：`cases.json` 与 `images/apartment.png` 位于同一目录树。清单示例中的坐标、数量仅展示格式，不是任何真实户型的标注：

```json
{
  "cases": [{
    "id": "apartment-01",
    "image": "images/apartment.png",
    "origin": "real_floorplan",
    "annotation": "human_verified",
    "expected": {
      "outline": [[0, 0], [8, 0], [8, 6], [0, 6]],
      "area": 48,
      "bedrooms": 1,
      "windows": 2,
      "doors": 1,
      "room_points": [["living", 2, 3], ["bedroom", 6.5, 3]],
      "opening_points": [["window", 2, 0], ["window", 6.5, 0], ["door", 4.5, 3.4]]
    }
  }]
}
```

运行：`python scripts/benchmark_quality.py --model <已接入模型> --manifest <cases.json>`。运行此命令会把清单图片发送给当前配置的 AI 服务；本轮没有执行真实图纸的外部 AI 调用。正常生成链路与缓存规则没有因为验收入口变化而改变。

原图与人工标注摘要随隔离验收记录保存；恢复时若原图或标注变了，拒绝复用旧记录。恢复数据存放在忽略的 `data/quality-benchmarks`，不修改用户任务，也不会把机器结果写成人工确认。

## 素材与发布检查

本轮检查官方家具目录 83 项：未发现重复 ID、缺少名称/分类/家族/变体/风格/尺寸或缺失 GLB/缩略图。几何尺寸、贴地和缩略图尺寸继续由现有后端真实素材测试验证；这不代表全部模型已完成视觉美观验收。

已有 CI 覆盖 Windows、Mac ARM 与 Intel，不重复增加另一套流程。本轮在 Windows 本地测试，不宣称已完成 Mac 实机或当前页面浏览器视觉验收。源码保留此前未提交修改，本轮不自动提交或推送。
